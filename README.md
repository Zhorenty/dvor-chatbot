# DVOR Telegram Bot

MVP-бот для спортивного объединения DVOR на Dart.

## Бизнес-документация

- Полная шпаргалка по пользовательским и админским сценариям, Google Sheets и операционным процессам: [`docs/BUSINESS_CHEATSHEET.md`](docs/BUSINESS_CHEATSHEET.md)
- Голос клуба (посты, рассылки, шаблоны бота): [`docs/VOICE.md`](docs/VOICE.md)

## Что умеет сейчас

- Личка (пользовательский сценарий):
  - `/start` — для новичков: короткий онбординг (квиз → трек → CTA записи); для уже существующих пользователей — классическое приветствие и меню
  <!-- TODO(subscription): вернуть трек/CTA PRO-абонемента в онбординге -->
  - `/trainings` или кнопка `Расписание` — сначала выбор категории (`Тренировки` / `Походы` / `Трейлы`), затем список по выбранной категории
    - в разделе `Тренировки` дата показывается лаконично с днем недели (например: `пн, 22.06.2026 19:00`)
  - `/book` или кнопка `Записаться` — сначала выбор категории, затем запись на конкретное мероприятие (только себя)
  - кнопка `Записать друга` — выбрать событие и ввести username/ФИО через запятую (до 5 человек), оплатить сумму `цена × число участников` одним чеком
  - после записи отправляет реквизиты/инструкцию оплаты с **inline-кнопками** под карточкой (`Я оплатил` / outdoor full·partial / бонус / промокод / отмена), привязанными к `bookingId`
- `/profile` и кнопка `Профиль` — открывает профиль со статистикой и прогрессом по бонусам
  <!-- TODO(subscription): вернуть внутри профиля кнопку `Абонемент` — статус (`Normal`/`PRO`), условия PRO и `Оформить` -->
- `/my_bookings` (или кнопка `Мои записи` внутри профиля) — открывает список записей (актуальные/прошедшие), включая записи друзей/гостей, которыми вы управляете
  - карточка записи: действия (оплата / перенос / отмена / повтор) — **inline** под сообщением
  - для походов/трейлов в шаге оплаты можно выбрать формат: полная оплата или предоплата (аванс/задаток) — кнопки на карточке оплаты
  - после записи на поход/трейл экипировка и расписание не дублируются вместе с реквизитами (их можно открыть отдельно до записи)
  - после предоплаты outdoor остаток вносится офлайн после события (через бота доплата не предлагается)
  - после оплаты пользователь отправляет в чат файл с подтверждением (документ/фото), после чего заявка уходит администратору
  - если in-memory флоу оплаты потерян (рестарт бота), чек всё равно принимается по активной записи `pending_payment` / `payment_rejected`; inline `Я оплатил` на карточке тоже ведёт к нужной записи по id
  - после отклонения оплаты статус остаётся `payment_rejected`; на reject-сообщении — inline CTA «отправить чек снова»
  - для записей в `pending_payment` автоматически отправляет напоминания об оплате (кнопка в напоминании привязана к конкретной записи)
  - отзыв после тренировки — оценка через **inline** (нижнее меню не подменяется)
  - кнопка `Помощь` — краткая справка по доступным действиям
- Личка (админский сценарий), главное меню:
  - `Список записавшихся` — выбор категории, затем список участников
  - `Заявки на оплату` / `/payments_queue` — выбор категории, затем очередь оплат на проверку; decision-кнопки inline, после решения markup исходного сообщения обновляется
  - `Управление расписанием` — CRUD тренировок / походов / трейлов в Google Sheets (карточки и кнопки под сообщением). После сохранения бот сам обновляет кэш; ручной `Обновить Google Sheets` не обязателен. Прошедшие строки бот удаляет из таблицы через 2 дня после окончания.
  - `Рассылка` — текст (HTML) и/или фото пользователям и/или в группу
  - `Инструменты`:
    - `Управление записями`:
      - `Список записей` -> сегмент (`Активные`/`Архивные`) -> категория -> запись по страницам
      - для записи: редактирование (`оплата`, `username`, `мероприятие`), восстановление и мягкое удаление в архив — действия на карточке **inline**
      - `Создать запись` -> категория -> мероприятие -> username -> статус -> подтверждение
      - после изменения бот спрашивает, нужно ли уведомить клиента (inline да/нет)
    - `Обновить Google Sheets` — синхронизация расписания, тренеров, команды DVOR и промокодов; если запись в таблицу включена, в очередь ставится и обновление срезов `FUNNEL` / `АНАЛИТИКА` / `ДВОРЯНЕ` / `ДЕЙСТВИЯ`
    - Срезы смотреть в таблице, не в боте: `FUNNEL` (воронка и фидбэк), `АНАЛИТИКА` (бронирования, бонусы, абонементы, экономика), `ДВОРЯНЕ`, `ДЕЙСТВИЯ`
    - `Абонементы` — фильтры (`Активные` / `Скоро истекают` / `На проверке` / `Отмененные`) и `Поиск`; `На проверке` — очередь модерации
    - `Поиск по пользователю`
    - `Диалог по @username` — сохранённая переписка с пользователем + пересылка исходных сообщений, где возможно
    - `Клиентское меню` — обычное пользовательское меню с кнопкой `Админ-меню` для возврата
  - `/approve_payment <id>`, `/approve_partial_payment <id>`, `/reject_payment <id>`
  - `/approve_subscription <id>`, `/reject_subscription <id>`, `/cancel_subscription <id>`
  - после модерации бот уведомляет пользователя; при `ADMIN_CHAT_ID` дублирует результат в админ-чат
  - при `ADMIN_CHAT_ID` автоматически шлёт экономическую сводку за завершённую неделю/месяц
- Групповой сценарий:
  - при входе нового участника бот отправляет welcome-сообщение в группу с url-кнопкой deep link `?start=start`
  - welcome автоматически удаляется позже (или после `/start` в личке)
  - анонсы расписания/рефералки в группе — с url-кнопкой «Записаться» (`?start=book`), если известен username бота
  - через ~2ч после старта оплаченной **тренировки** — мягкий анонимный запрос отзыва в личке (inline-оценка); готовый ответ уходит в `ADMIN_CHAT_ID`
  - для **походов/трейлов** отзыв запрашивается на следующий день после даты окончания в `12:00` по `TIMEZONE_OFFSET_HOURS` (однодневный — после даты старта; многодневный — после `date_to`)
  - бот публикует анонс тренировки по правилам времени:
    - если тренировка в `16:00` или позже — в `12:00` в день тренировки
    - если тренировка раньше `16:00` — в `20:00` за день до тренировки
  - регулярная рассылка расписания в группу (`TARGET_CHAT_ID`, таймзона `TIMEZONE_OFFSET_HOURS`):
    - воскресенье `18:30`
    - вторник `10:00`
    - четверг `10:00`
  - рассылка реферальной программы в группу: среда `10:00`
  - автоматические анонсы в группе идут через один слот с приоритетом
    (сегодня/завтра → мест нет → расписание → мало мест → рефералка):
    более важное сообщение удаляет предыдущий анонс и заменяет его;
    более слабое не отправляется, пока слот занят (TTL слота 3 часа)
  - антиспам в целевой группе: удаляет рекламу заработка/удалёнки с призывом «в лс» и банит отправителя
    - админы из `ADMIN_USER_IDS` не проверяются
    - при заданном `ADMIN_CHAT_ID` бот шлёт короткое уведомление о срабатывании
    - выключается через `ANTISPAM_ENABLED=false`
- Источники расписания:
  - `static` (по умолчанию) — расписание в коде
  - `google_sheets` — расписание из Google Sheets CSV с периодическим sync и fallback на последний валидный кэш

## Структура проекта

- `bin/dvor_bot.dart` — entrypoint; один shared SQLite handle на booking/onboarding/subscription
- `lib/src/config/app_config.dart` — конфигурация из CLI/env/.env
- `lib/src/telegram/telegram_client.dart` — Telegram Bot API клиент
- `lib/src/bot/bot_runner.dart` + `lib/src/jobs/job_scheduler.dart` — long polling и фоновые джобы
- `lib/src/bot/handlers/private_handlers.dart` — facade private-сценариев (+ `private/*.part.dart`)
- `lib/src/bot/handlers/group_handlers.dart` — welcome flow и антиспам в группе
- `lib/src/application/group_spam_detector.dart` — эвристики рекламы заработка / удалёнки
- `lib/src/data/static_schedule_repository.dart` — статичное расписание тренировок
- `lib/src/data/google_sheets_schedule_repository.dart` — расписание из Google Sheets CSV
- `lib/src/data/google_sheets_api_writer.dart` — запись дашборда воронки в Google Sheets (лист `FUNNEL`)
- `lib/src/data/google_sheets_schedule_catalog_repository.dart` — точечный CRUD вкладок `Тренировки` / `Походы` / `Трейлы` (без wipe)
- `lib/src/jobs/schedule_retention_job.dart` — удаление прошедших событий из таблицы через 2 дня
- `lib/src/data/sqlite_booking_repository.dart` — SQLite-хранилище записей и оплат
- `lib/src/data/job_dedupe_repository.dart` — идемпотентность promo/broadcast джобов
- `lib/src/messages/message_templates.dart` — шаблоны сообщений (+ `templates/*.part.dart`)
- `lib/src/messages/html_escaper.dart` — общий HTML escape для Telegram
- `test/` — unit-тесты (включая `concurrency_safety_test.dart`)

## Конфигурация

Создайте `.env` рядом с `pubspec.yaml`:

```env
BOT_TOKEN=123456:ABCDEF
TARGET_CHAT_ID=-1001234567890
SEND_GROUP_FALLBACK=true
POLL_TIMEOUT_SECONDS=25
SCHEDULE_SOURCE=static
GOOGLE_SHEETS_CSV_URL=
SCHEDULE_SYNC_INTERVAL_SECONDS=300
ADMIN_USER_IDS=123456789
ADMIN_CHAT_ID=-1001234567890
BOOKINGS_DB_PATH=data/bookings.sqlite
PENDING_PAYMENT_TTL_MINUTES=30
TIMEZONE_OFFSET_HOURS=3
ANTISPAM_ENABLED=true
ONBOARDING_DRIP_ENABLED=true
TRAINING_FEEDBACK_ENABLED=true
GROUP_INVITE_NUDGE_ENABLED=true
GOOGLE_SHEETS_WRITE_ENABLED=false
GOOGLE_SHEETS_CREDENTIALS_PATH=
GOOGLE_SHEETS_SPREADSHEET_ID=
GOOGLE_SHEETS_WRITE_SHEET_TITLE=FUNNEL
GOOGLE_SHEETS_WRITE_INTERVAL_SECONDS=300
GOOGLE_SHEETS_RECENT_ACTIONS_LIMIT=200
LOG_LEVEL=info
```

- `ONBOARDING_DRIP_ENABLED` — квиз/nudges только для новичков (строки в БД до первого запуска фичи помечаются как legacy и не затрагиваются).
- `TRAINING_FEEDBACK_ENABLED` — анонимный отзыв: тренировки через ~2ч после `startsAt`; походы/трейлы на следующий день после даты окончания в `12:00` (таймзона `TIMEZONE_OFFSET_HOURS`).
- `GROUP_INVITE_NUDGE_ENABLED` — мягкие напоминания в личку тем, кто пользуется ботом, но не состоит в группе DVOR. Нужны `TARGET_CHAT_ID` и бот-админ в группе (`getChatMember` + `chat_member` leave). Максимум 3 сообщения: через сутки после Start, затем через 7 и 14 дней.

### Админские срезы в Google Sheets

SQLite остаётся источником правды. Если включить запись, бот раз в `GOOGLE_SHEETS_WRITE_INTERVAL_SECONDS` **пересобирает** четыре bot-owned вкладки (каждую по отдельности, delete+create):

- `FUNNEL` — воронка новичка: KPI, таблицы, графики, квиз, фидбек
- `АНАЛИТИКА` — бронирования, бонусы/рефералы, абонементы, экономика текущей недели и текущего месяца
- `ДВОРЯНЕ` — рейтинг по прошедшим тренировкам
- `ДЕЙСТВИЯ` — лента DM-лога (`GOOGLE_SHEETS_RECENT_ACTIONS_LIMIT`, по умолчанию 200, без админов)

Входные листы (`Тренировки`, `Походы`, `Трейлы`, `Тренерский штаб`, `Команда DVOR`, `Промокоды`, `КАК ЗАПОЛНЯТЬ`) бот при экспорте не трогает. Старый лист `bot_bookings` удаляется. Bot-owned вкладки руками не править — следующий sync их пересоздаёт.

Кнопка `🔄 Обновить Google Sheets` сначала подтягивает входные листы в кэш бота, затем (если запись включена) ставит в очередь тот же экспорт срезов. Не ждите мгновенного появления данных в таблице: запись идёт в фоне.

1. В Google Cloud: включить **Google Sheets API**, создать **service account**, скачать JSON-ключ.
2. В таблице: «Настройки доступа» → email сервис-аккаунта с правом **Редактор**.
3. Положить JSON на сервер (не в git), например `secrets/google-sheets.json`.
4. В `.env`:

```env
GOOGLE_SHEETS_WRITE_ENABLED=true
GOOGLE_SHEETS_CREDENTIALS_PATH=/app/secrets/google-sheets.json
GOOGLE_SHEETS_SPREADSHEET_ID=1pA6XEjrAAgJT7rFVe86JdfHSl8NCPMJ4Wp7i9JN6a5Q
GOOGLE_SHEETS_WRITE_SHEET_TITLE=FUNNEL
GOOGLE_SHEETS_WRITE_INTERVAL_SECONDS=300
GOOGLE_SHEETS_RECENT_ACTIONS_LIMIT=200
```

`GOOGLE_SHEETS_SPREADSHEET_ID` можно не задавать, если в `GOOGLE_SHEETS_CSV_URL` уже есть `/spreadsheets/d/<id>/`. В Docker JSON монтируется через `./secrets:/app/secrets:ro` в `compose.yaml`. После изменения `.env` — перезапуск compose.

Можно задавать и через CLI (имеет более высокий приоритет):

```bash
dart run bin/dvor_bot.dart --token=123456:ABCDEF --target-chat-id=-1001234567890 --schedule-source=google_sheets --google-sheets-csv-url="https://docs.google.com/spreadsheets/d/.../export?format=csv&gid=0"
```

### Формат Google Sheets CSV

Вкладки входных листов: `Тренировки`, `Походы`, `Трейлы`, `Тренерский штаб`, `Команда DVOR`, `Промокоды`. Бот ходит по **gid**, не по имени вкладки. Строка 1 — рабочие заголовки (русские имена; английские алиасы парсер тоже ест). Подсказка — в заметке шапки и в колонке `статус` правее данных. `статус` бот не читает. Лист `КАК ЗАПОЛНЯТЬ` бот не читает. Листы `FUNNEL`, `АНАЛИТИКА`, `ДВОРЯНЕ`, `ДЕЙСТВИЯ` руками не править.

Оформить входные листы заново (без wipe данных):

```bash
dart run tool/format_input_sheets.dart --credentials=secrets/google-sheets.json
```

Тренировки (лист `gid=0`, URL задается через `GOOGLE_SHEETS_CSV_URL`), обязательные колонки:

- `название` (алиас `title`)
- `starts_at` (например `2026-06-05 19:00` или `05.06.2026 19:00`) **или** пара `дата` + `время` (алиасы `date` / `time`)
- `место` (алиас `location`)

Опциональные колонки:

- `карта` (алиасы `location_url`, `maps_url`) — ссылка на Яндекс Карты; если пусто, бот ищет место в Яндекс Картах по колонке `место`
- `лимит` (алиасы `limit`, `participants_limit`)
- `тренер` (алиас `coach`)
- `заметки` (алиас `notes`)
- `цена` (алиас `price`)
- `тренеры_в_лимите` (алиасы `include_trainers`, `include_trainers_in_participants`; `1/0`, `true/false`, `yes/no`, `да/нет`) — считать тренеров из whitelist участниками для лимита мест
- `без_промокода` (алиас `promo_restricted`)

Whitelist тренеров для автозаписи без шага подтверждения оплаты задается в `lib/src/config/trainer_booking_whitelist.dart`.
Тренеры из этого списка также видят кнопку `Список записавшихся` в клиентском меню: сразу открывается список участников по категории `Тренировки` (без выбора категории).
Если пользователь одновременно в тренерском whitelist и в команде DVOR, применяется сценарий тренерского штаба.

Список тренеров для кнопки `Тренерский штаб` загружается из отдельного листа (`gid=195037978`).
Используются колонки:

- `имя` (обязательно; алиас `name`)
- `username` (обязательно; алиасы: `link`, `telegram`, `tg`, `ссылка`)
- `описание` (обязательно; алиас `description`)
- `роль` (опционально; алиас `role`)

Команда DVOR для бесплатной записи загружается из отдельного листа (`gid=2001400867`).
Используются колонки (заголовки нормализуются: lowercase, пробелы → `_`, `ё` → `е`, поддерживаются алиасы):

- `username` (алиасы: `telegram`, `tg`, `link`, `юзернейм`) — Telegram-username участника команды (`@name` или `name`), обязательно
- `имя` — для людей, бот не читает

Строки без username пропускаются. Участники команды получают запись без шага оплаты (учитываются в лимите мест).

Походы и трейлы загружаются из тех же Google Sheets автоматически:

- Походы: `gid=294119056`
- Трейлы: `gid=1220729038`

Одинаковые колонки:

- `название` (обязательно; алиас `title`)
- `дата_с` (обязательно; алиас `date_from`)
- `дата_по` (опционально; алиас `date_to`; пусто = один день)
- `описание` (обязательно; алиас `description`)
- `место` (алиас `location`)
- `цена` (алиас `price`)
- `предоплата` (опционально; 1–100, пусто = `50`; алиасы: `prepay_percent`, `prepayment_percent`, `prepaid_percent`, `prepay`, `процент_предоплаты`)
- `лимит` (алиас `limit`)
- `экипировка` / `план` (алиасы `equipment` / `itinerary`)

Промокоды загружаются из отдельного листа (`gid=432112868`) той же таблицы.
Используются колонки (заголовки нормализуются: lowercase, пробелы → `_`, поддерживаются алиасы):

- `промокод` (алиасы: `code`, `promocode`, `код`) — текст промокода, обязательно
- `скидка` (алиасы: `discount_percent`, `discount`, `percent`, `процент`) — целое число 1–100, знак `%` допускается; обязательно
- `категории` (алиасы: `categories`, `category`, `категория`, `тип`) — `все` / `Тренировки` / `Походы` / `Трейлы` или список через запятую / `;`; пустое значение либо `все`/`all` означает все категории. Токены: `тренировки` / `trainings`, `походы` / `hikes`, `трейлы` / `trails`.
- `одноразовый` (алиас `single_use`)

Строки без `промокод`/`code` или с невалидной скидкой пропускаются. При дублировании кода побеждает последняя строка.
Промокод можно ввести на шаге подтверждения оплаты (кнопка `🎟 Ввести промокод`): при скидке меньше 100% пересчитывается сумма к оплате, при 100% запись становится бесплатной без подтверждения оплаты.

## Локальный запуск

1. Установите Dart SDK (3.5+).
2. Установите зависимости:
   - `dart pub get`
3. Запустите бота:
   - `make bot` (или `dart run bin/dvor_bot.dart`)

## Деплой

Прод: Timeweb, `/opt/dvor-chatbot-project`. Подробнее: [`docs/DAILY_OPS_TIMEWEB.md`](docs/DAILY_OPS_TIMEWEB.md).

- Обычный апдейт на сервере: `bash scripts/update_and_logs.sh` (`git pull` + сборка с кэшем Docker).
- Полный деплой (новые пакеты, Dockerfile, `.env`, воронка Sheets): с Mac после commit + push — `./scripts/full_deploy.sh`. На VPS — `bash scripts/full_deploy.sh` (сборка **без кэша**, recreate контейнера).

### Вариант 1: Docker

1. Убедитесь, что в `.env` задан путь БД:
   - `BOOKINGS_DB_PATH=data/bookings.sqlite`
2. Создайте каталог для постоянного хранения SQLite:
   - `mkdir -p data`
3. Однократно (перед первым запуском с volume) перенесите текущую БД из контейнера, если она уже есть:
   - `docker cp dvor-chatbot:/app/data/bookings.sqlite data/bookings.sqlite 2>/dev/null || true`
4. Запустите сервис через Docker Compose:
   - `docker compose up -d --build`
5. `compose.yaml` уже монтирует `./data` в `/app/data` и `./secrets` в `/app/secrets` (read-only). JSON сервис-аккаунта кладите в `./secrets/`, путь в `.env` — `/app/secrets/google-sheets.json`.
6. Проверьте логи:
   - `docker logs -f dvor-chatbot`

### Вариант 2: systemd (Linux)

1. Скомпилируйте бинарник:
   - `dart compile exe bin/dvor_bot.dart -o dvor_bot.run`
2. Создайте unit-файл `dvor-bot.service` с `Restart=always`.
3. Передайте `EnvironmentFile=/path/to/.env`.
4. Запустите:
   - `sudo systemctl daemon-reload`
   - `sudo systemctl enable --now dvor-bot`
   - `sudo systemctl status dvor-bot`
