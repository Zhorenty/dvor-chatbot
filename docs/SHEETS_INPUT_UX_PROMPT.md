# Промпт: UX заполнения входных листов DVOR Google Sheets

Скопируй блок ниже в новый чат Cursor (Agent). Приложи скриншоты текущих листов, если они есть.

Визуальный слой (freeze, цвета FUNNEL, галки, даты, notes, фильтр, вкладки по-русски, лист `КАК ЗАПОЛНЯТЬ`) **уже сделан**. Этот запрос — не «сделай красиво ещё раз», а **понятнее заполнять и меньше молчаливых ошибок**.

---

Ты работаешь в репозитории `dvor-chatbot` (Dart Telegram-бот DVOR). Нужен UX-проход по **входным** листам рабочей Google Таблицы: чтобы человек из команды заполнял расписание, штаб, команду и промокоды без знания внутренних имён колонок и без сюрпризов «строка есть, бот её проглотил».

Таблица: `https://docs.google.com/spreadsheets/d/1pA6XEjrAAgJT7rFVe86JdfHSl8NCPMJ4Wp7i9JN6a5Q/edit`

Уже есть: `tool/format_input_sheets.dart`, контракт колонок в `lib/src/data/google_sheets_input_ui.dart`, лист `КАК ЗАПОЛНЯТЬ`. Повторять оформление с нуля не надо — **достроить** UX и при необходимости расширить парсеры + прогнать форматтер.

## Жёсткие правила (сломать бота нельзя)

1. **Не трогай лист `FUNNEL`.** Бот его пересоздаёт. Не меняй gid, не wipe, не переименовывай ничего в `FUNNEL`.
2. **Не делай `replaceSheet` / wipe / delete+create по входным листам.** Данные остаются.
3. **Строка 1 = CSV-заголовки.** Парсеры: `rows.first` header, `rows.skip(1)` данные. Не вставляй титул, легенду, пустые строки и merged-шапку **над** таблицей. Подсказку — note шапки, лист `КАК ЗАПОЛНЯТЬ`, или **формульный статус правее данных** (колонка, которую парсер не использует).
4. **Не переименовывай заголовки, пока нет алиасов в парсере + тестов.** Нормализация: trim, lowercase, пробелы → `_`, у части листов ещё `ё` → `е`. Сейчас **нет** русских алиасов у тренировок: `title` / `location` / `date` / `time` / `notes` / `price`. У походов/трейлов нет алиасов у `title` / `date_from` / `date_to` / `description` / `price`.
5. Не двигай **gid**. Бот ходит по gid. Имя вкладки можно оставить человеческим (уже: «Тренировки», «Походы», …).
6. Не коммить секреты (`.env`, `secrets/*.json`).
7. Голос клуба (`docs/VOICE.md`) — только для текстов **бота**. Подписи в таблице — короткие рабочие, без маркетинга.
8. **Не** пиши оформление входных листов в `GoogleSheetsFunnelDashboard` и **не** экспортируй их джобой каждые 5 минут.
9. Сначала **прочитай живые листы** (CSV по gid / Sheets API). Потом план (что нашёл / что меняешь), потом делай. Не выдумывай колонки «на всякий случай», не удаляй те, что парсятся.
10. После правок: выгрузить CSV каждого gid (строка 1 = заголовки, строка 2 = первая запись или осознанный пробел), `dart format bin lib test tool`, `dart analyze --fatal-infos --fatal-warnings`, `dart test`. Обновить `README.md` («Формат Google Sheets CSV») и `docs/BUSINESS_CHEATSHEET.md` («Как вести расписание»), если менялись заголовки, колонки или правила заполнения.

Код парсеров:

- тренировки / походы / трейлы: `lib/src/data/google_sheets_schedule_repository.dart`
- штаб: `lib/src/data/google_sheets_trainer_directory_repository.dart`
- команда: `lib/src/data/google_sheets_dvor_team_repository.dart`
- промо: `lib/src/data/google_sheets_promo_code_repository.dart`
- UI-спека: `lib/src/data/google_sheets_input_ui.dart`
- прогон вида: `dart run tool/format_input_sheets.dart --credentials=secrets/google-sheets.json`

## Что уже сделано (не ломай, не делай заново)

- Freeze row 1, banded rows, рамки, ширины, filter, notes на шапке, даты, числа, чекбоксы, dropdown категорий промо, подсветка дыр и дублей кода.

## Аудит: что мешает заполнять (приоритет)

Работай сверху вниз. Не расползайся в редизайн бота, запись, оплату, FUNNEL-дашборд.

### P0 — Шапка на русском, бот не падает

Человек видит `title`, `include_trainers`, `promo_restricted`, `date_from`. Notes только по наведению. Это главный UX-долг.

Сделай так:

1. Алиасы в парсере + тесты.
2. Переименуй **только row 1** на короткие рабочие русские имена (без пробелов или с пробелами — нормализация уже схлопывает пробелы в `_`).
3. Обнови `google_sheets_input_ui.dart` (header + notes) и прогони `format_input_sheets.dart`, чтобы notes/validation сели на новые имена.
4. CSV: первая строка — новые заголовки, данные на месте.

Черновик имён (можно короче, не синонимы-эссе):

| Лист | сейчас | предложи, если алиас есть / добавлен |
|---|---|---|
| Тренировки | `title` | `название` |
| | `date` / `time` | `дата` / `время` |
| | `location` | `место` |
| | `location_url` | `карта` или оставь (уже есть `maps_url`…) |
| | `include_trainers` | `тренеры_в_лимите` (алиас уже есть) |
| | `promo_restricted` | `без_промокода` (алиас уже есть) |
| | `coach` | `тренер` (алиас уже есть) |
| | `price` / `limit` / `notes` | `цена` / `лимит` / `заметки` |
| Походы/трейлы | `title` `date_from` `date_to` `description` | `название` `дата_с` `дата_по` `описание` |
| | `prepay_percent` | `предоплата` (алиас уже есть) |
| Штаб | `name` `username` `role` `description` | `имя` / оставить `username` (это ник) / `роль` / `описание` |
| Команда | `name` `username` | `имя` можно; `username` лучше не трогать — это контракт whitelist |
| Промо | `code` `discount_percent` `categories` `single_use` | алиасы уже есть: `промокод` `скидка` `категории` `одноразовый` |

Не переименовывай в что-то, чего парсер не ест. После смены — админ-кнопка «Обновить Google Sheets» должна подтянуть те же события.

### P1 — Видно, уйдёт ли строка в бота

Сейчас дырявая строка **молча skip**. Человек думает, что карточка в боте появится.

Сделай колонку статуса **правее данных** (например с колонки `L`/`K`…), заголовок вроде `статус` / `_status`. Парсеры лишние колонки игнорируют — **не** клади это в row-1 слева и не сдвигай CSV-поля.

Формула (locale таблицы `ru_RU`, разделитель `;`): готово / чего не хватает, без KPI-простыни. Условное форматирование уже красит дыры — статус должен **говорить словами**.

Не пиши статус ботом в эти листы.

### P2 — Порядок полей и одинаковые формы

Парсеры ищут колонки **по имени, не по индексу**. Порядок менять можно.

- **Походы:** обязательное `description` сейчас последнее из 10 — легко не заполнить. Подвинь обязательные влево: название, даты, описание, место, цена, предоплата, лимит, экипировка, план.
- **Трейлы:** тот же контракт, что походы, но нет `prepay_percent` / `equipment` / `itinerary`. Добавь **пустые** колонки с теми же заголовками, что на походах (после алиасов — теми же русскими). Не выдумывай новые смыслы. Пустая предоплата = 50%, это уже так.
- **Тренировки:** обязательные уже слева — ок. Чекбоксы можно ближе к краю, чтобы не рвать «место → карта → тренер».

После перестановки обнови спеку ширин/notes и прогони форматтер. CSV-проверка: все прежние поля на месте, данные в тех же строках.

### P3 — Меньше сюрпризов в ячейках

- **Время:** нет time-picker validation, только формат. Добавь понятный ввод (validation или note «19:30»). Не ломай CSV вроде `08:30` / `8:30` — парсер оба ест.
- **`prepay_percent` пусто = 50%:** в ячейке не видно. Note уже есть; в статус-формуле пиши «предоплата 50% по умолчанию», не подставляй фейковое число в пустые ячейки (это изменит смысл, если потом дефолт в коде сменят).
- **`date_to` пусто = один день:** то же — статус/note, не автозаполняй датой с, если человек оставил пусто.
- **Промо `categories`:** dropdown жёстких комбинаций; живые значения в другом порядке (`Походы, Тренировки, Трейлы`) выглядят «не из списка» при `strict: false`. Лучше: три понятных выбора + `все`, без дублирования перестановок. Не переходи на три чекбокса, пока парсер ест **одну** ячейку-список.
- **`coach`:** свободный текст, штаб — другой лист. Dropdown имён со штаба (ONE_OF_RANGE на колонку имён) — ок, `strict: false`, чтобы разовые тренеры проходили.
- **`include_trainers`:** смысл неочевиден (считать тренеров в лимите мест, не «пригласить тренера»). Русское имя + note обязательны.
- **Штаб:** строка с именем без `@username` и описания бот пропускает. Статус это должен сказать.
- **Команда DVOR:** в `username` только ник. Побочная колонка `имя` уже есть — не клади ФИО в username.

### P4 — Место для новых строк и мусор

Форматтер режет сетку до «данные + 40». Filter/validation живут в этом диапазоне. 41-я строка выпадает из вида.

- Запас не 40, а достаточно большой (например 150–200 пустых), **или** не режь `rowCount` так агрессивно, но не возвращай 1000 чекбокс-строк.
- Чекбоксы только на буфере, не на тысяче пустых. Пустая строка с двумя `FALSE` не должна считаться «начатой» (это уже учтено в CF — не сломай).
- **Походы:** под шапкой были пустые ряды, у названия живого тура ведущий пробел. Пустые ряды под шапкой убери, если в них нет данных. Ведущие пробелы в `title` можно trim **только** если не меняешь смысл; парсер уже `trim` при чтении — в таблице пробел всё равно выглядит грязно, почисти явно мусорные.

Не удаляй живые события. Не вставляй пример-строки с фейковым названием — бот их опубликует.

### P5 — Лист «КАК ЗАПОЛНЯТЬ»

Сейчас якоря и gid. Для заполняющего gid не нужен.

Перепиши коротко: по вкладке — обязательные поля, что будет если пусто, что сделать после правки (`Обновить Google Sheets` в боте). Без маркетинга, без gid в первом экране (gid можно мелкой строкой внизу для админа). Не дублируй роман на каждом листе.

### Вне скоупа (не делать в этом запросе)

- Перенос расписания из Sheets в админку бота.
- Автосинк без кнопки «Обновить».
- Писать входные листы из бота / джобы.
- Сводить whitelist тренеров из `trainer_booking_whitelist.dart` и листы в один источник (это отдельная продуктовая задача: сейчас штаб ≠ бесплатная запись ≠ команда DVOR).
- Редизайн FUNNEL.
- Архив прошедших тренировок на отдельный лист (бот и так показывает upcoming; перенос старья — только если явно попросит пользователь).

## Проверка для человека, который заполняет

- Открыл «Тренировки» — шапка по-русски, понятно куда писать, без словаря `include_trainers`.
- Неполная строка: цвет **и** слова в статусе, не тишина в боте.
- Новый ряд влезает в таблицу с теми же галками/датами, не «голая» строка за фильтром.
- Поход и трейл заполняются одинаково.
- После правок «Обновить Google Sheets» показывает те же карточки, что в таблице.
- CSV: нет пустой служебной строки между шапкой и первой записью на рабочих листах.

Не коммить `.env` и `secrets/*.json`. Сначала план по факту открытых листов, потом код/алиасы, потом шапка, потом форматтер, потом CSV + тесты + docs.
