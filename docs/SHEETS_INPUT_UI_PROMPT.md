# Промпт: UI входных листов DVOR Google Sheets

Скопируй блок ниже в новый чат Cursor (Agent). Приложи скриншоты текущих листов, если они есть.

---

Ты работаешь в репозитории `dvor-chatbot` (Dart Telegram-бот DVOR). Нужно пройтись по **входным** листам рабочей Google Таблицы и сделать их таким же ясным и аккуратным UI, как лист `FUNNEL`, но это **не дашборд**.

`FUNNEL` — витрина, бот её пересоздаёт. Остальные листы — **формы ввода**: люди заполняют строки, бот читает CSV. Задача: проще заполнять, меньше ошибок, визуально в одном стиле с FUNNEL.

Таблица: `https://docs.google.com/spreadsheets/d/1pA6XEjrAAgJT7rFVe86JdfHSl8NCPMJ4Wp7i9JN6a5Q/edit`

## Жёсткие правила (сломать бота нельзя)

1. **Не трогай лист `FUNNEL`.** Его пишет бот. Не меняй gid, не чисти, не переименовывай в FUNNEL ничего другого.
2. **Не делай `replaceSheet` / wipe / delete+create по входным листам.** Данные (тренировки, походы, люди, промокоды) должны остаться.
3. **Строка 1 = заголовки колонок, которые ест CSV.** Парсеры берут `rows.first` как header и `rows.skip(1)` как данные. Не вставляй над таблицей титул, легенду, пустые строки, объединённые шапки из двух рядов. Подсказку — в **заметку ячейки** (comment/note) шапки, в описание листа, или на отдельный лист `LEGEND` / `КАК ЗАПОЛНЯТЬ`, который бот не читает.
4. **Не переименовывай технические заголовки**, пока не добавишь алиасы в парсер. Нормализация: trim, lowercase, пробелы → `_`. Для тренировок сейчас почти нет русских алиасов у `title` / `starts_at` / `location`.
5. Не двигай **gid** листов. Бот ходит по gid, не по имени вкладки. Имя вкладки можно сделать человеческим.
6. Не коммить секреты. JSON сервис-аккаунта не в git.
7. Голос клуба (`docs/VOICE.md`) — только если пишешь пользовательские тексты бота. Подписи в таблице — короткие рабочие, без маркетинга.

## Референс стиля FUNNEL (цвета 0..1)

- Бумага: `rgb(0.98, 0.97, 0.94)`
- Чернила: `rgb(0.12, 0.16, 0.14)`
- Шапка листа / таб: `rgb(0.12, 0.23, 0.18)` + текст `rgb(0.96, 0.95, 0.91)`
- Шапка таблицы: `rgb(0.83, 0.88, 0.83)`
- Секция: `rgb(0.22, 0.38, 0.30)`
- KPI-зелёный / песочный / голубой — только если на листе есть маленькая сводка **формулами** справа или сверху **вне** диапазона CSV… нет: сводку не ставить в те же колонки, что читает бот. Либо отдельный блок правее данных (начиная с колонки далеко справа, которую парсер просто не использует), либо отдельный лист. Предпочтительно: только сама таблица + фильтр + валидация, без KPI.

Входной лист должен ощущаться как **аккуратная таблица**: freeze row 1, banded rows, рамки, ширина колонок, скрыть лишние пустые колонки справа, tab color как у FUNNEL.

## Листы и контракт колонок

Открой таблицу, сопоставь вкладки по **gid**. Если имя вкладки другое — оставь gid, работай с тем листом.

### 1) Тренировки — `gid=0`

Обязательно: `title`, `location`, и либо `starts_at`, либо пара `date` + `time`.  
Формат даты: `2026-06-05 19:00` или `05.06.2026 19:00`.

Опционально (уже парсятся): `participants_limit`, `coach`/`тренер`, `notes`, `price`, `location_url`, `include_trainers_in_participants` (1/0, true/false, да/нет), `promo_restricted` / `без_промокода`.

UX:

- Заморозить шапку.
- `starts_at` — формат даты-времени + data validation «дата».
- `participants_limit`, `price` — число.
- Булевы колонки — **чекбоксы** (CSV уйдёт как TRUE/FALSE, парсер это ест).
- У шапки каждой колонки — note: зачем поле и пример.
- Conditional formatting: красная/песочная заливка, если пусты `title` / `location` / дата при непустой строке.
- Не оставляй «пример-строки» с фейковым названием — бот их опубликует.

Код: `lib/src/data/google_sheets_schedule_repository.dart` (`_parseCsv`).

### 2) Походы — `gid=294119056`

Обязательно: `title`, `date_from`, `description`.  
Опционально: `date_to`, `location`/`место`, `equipment`/`экипировка`, `itinerary`/`расписание`, `price`, `prepay_percent` (1–100, алиасы `предоплата`), `participants_limit`.

UX: даты как даты; `prepay_percent` число 1–100 + note «пусто = 50%»; широкая колонка `description` с wrap; чекбоксы не выдумывать.

Код: тот же репозиторий, `_parseOutdoorCsv`.

### 3) Трейлы — `gid=1220729038`

Тот же контракт, что походы. Визуально отличить tab color / заголовок вкладки (`Трейлы`), чтобы не путать с походами.

### 4) Тренерский штаб — `gid=195037978`

Обязательно: `name`, `link`, `description` (алиасы: имя, ссылка, описание, telegram, …).  
Опционально: `role` / `роль`.

UX: `link` — `@username` или URL; note на шапке. Пустые name/link/description строки бот пропускает.

Код: `lib/src/data/google_sheets_trainer_directory_repository.dart`.

### 5) Команда DVOR — `gid=2001400867`

Нужен `username` (алиасы: telegram, tg, link, юзернейм). Строки без username пропускаются. Это whitelist бесплатной записи.

UX: одна явная колонка username, note «@name или name»; можно колонки ФИО/роль справа — бот их проигнорирует, людям удобно. Не клади в колонку username ничего кроме ника.

Код: `lib/src/data/google_sheets_dvor_team_repository.dart`.

### 6) Промокоды — `gid=432112868`

Обязательно: `code`, `discount_percent` (1–100, `%` можно).  
Опционально: `categories` (через запятую; пусто/`все`/`all` = все категории), `single_use` (чекбокс).

UX: dropdown на `categories` из значений вроде `trainings,hikes,trails` и `все` (проверь, какие строки категорий парсер принимает в `_parseCategories`); скидка — число 1–100; дубли кода: побеждает последняя строка, подсвети дубли условным форматированием.

Код: `lib/src/data/google_sheets_promo_code_repository.dart`.

## Как делать (предпочтительный путь)

1. Сначала **прочитай живые листы** (Sheets API / CSV export по gid / скриншоты пользователя). Зафиксируй фактические названия вкладок и текущие заголовки. Не выдумывай колонки, которых нет, и не удаляй те, что парсятся.
2. Оформи **на месте**: freeze, column widths, wrap, header fill/bold, banded rows, borders, tabColor, filter на строке 1, notes на шапке, data validation, conditional formatting, чекбоксы для булевых.
3. Если нужен титул «как заполнять» — лист `КАК ЗАПОЛНЯТЬ` с якорями на каждый gid, без изменения row 1 рабочих листов.
4. Защита: лист `FUNNEL` — только бот (если есть доступ); на входных листах можно защитить только row 1 (шапка), данные открыты.
5. **Не** пиши это оформление в `GoogleSheetsFunnelDashboard` и **не** экспортируй входные листы джобой каждые 5 минут — иначе затрутся ручные правки.
6. Если без смены заголовков на русские не обойтись — сначала алиасы в парсере + тесты, потом переименуй шапку. Для тренировок `title`/`starts_at`/`location` алиасов сейчас нет.
7. Проверка: выгрузить CSV каждого gid и убедиться, что первая строка — те же технические заголовки, вторая — первая запись. Прогнать `dart format`, `dart analyze --fatal-infos --fatal-warnings`, `dart test`. Если код не менялся — тесты всё равно не ломай.
8. Документация: если поменялись заголовки или добавился лист-легенда — `README.md` (блок «Формат Google Sheets CSV») и `docs/BUSINESS_CHEATSHEET.md` («Как вести расписание»).

## Что должно получиться для человека, который заполняет

- Открыл вкладку — сразу таблица, шапка на месте, понятно куда писать.
- Дата выбирается, а не вбивается криво.
- Да/нет — галка, не «true».
- Обязательные пустые ячейки видны.
- Не нужно помнить gid и внутренние имена: вкладки названы «Тренировки», «Походы», «Трейлы», «Тренерский штаб», «Команда DVOR», «Промокоды».
- После правок по-прежнему работает админ-кнопка «Обновить Google Sheets».

Не расползайся в редизайн бота. Не коммить `.env` и `secrets/*.json`. Сначала покажи план по факту открытых листов (что нашёл / что поменяешь), потом делай.
